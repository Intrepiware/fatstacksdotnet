How to review

Open the collapsible Mock controls — not part of design panel to switch states or choose the next save outcome. New/Save/Continue/Cancel use simulated outcomes. Returning to another page reloads the fixtures; no financial data is persisted. One persona is supported: the book owner.

Design references and spec overrides

The current WPF main window and journal editor are the design baseline. Earlier screenshots are used for spacing and the account rail only. The current spec overrides their older layouts: Payee with optional italic Description, status between Account and Debit, centered Debit/Credit headings with right-aligned values, live totals, mutually exclusive amount input, and reset warning/confirmation. The journal totals footing, row-tracking cues, and inline validation cues are now backported into spec.md and contracts/desktop-ui.md: the footing shows a bold Totals: prefix with Balanced or the short side named in red, numeric totals sit directly under their Debit/Credit columns with shared scrollbar-gutter alignment and without repeated labels or currency codes, the over-side total is red while unequal, each posting row shows a line number, alternate rows carry a continuous register stripe, and the hovered or focused row is highlighted in the register's selected-row color while inputs stay white. A line named in the reset warning shows an amber line number; a line with a validation error shows a 2px red input border and a red line-number pill that clear live when fixed. The WPF editor does not implement these additions yet.

Deliberately not mocked

  • Connections, account setup, delete confirmation, schema maintenance, and installation.
  • US4 reconciliation editing and US5 securities workflows. Existing states are displayed read-only; the main window retains its current blank Security/Quantity detail columns.
  • Database writes, real concurrency, credentials, durable financial persistence, and accounting validation beyond the small UI demonstration.
  • Native WPF window management, calendar popups, exact account suggestion routing, performance, and Windows screen-reader/high-DPI acceptance.
  • Paging: the current desktop register scrolls and filters; this mock-up does not introduce pagination.
