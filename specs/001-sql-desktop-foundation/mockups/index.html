How to review

Open the collapsible Mock controls — not part of design panel to switch states or choose the next save/status outcome. On the main window, each line for the selected account appears as its own row in the upper register: use ↑/↓ to step between transactions and press R, C, or U (or click a row's compact 3-state C control). The lower entry-details pane's C column is read-only. Reload simulates a refresh and retains status changes made on that page. Returning to another page reloads the fixtures; no financial data is persisted. One persona is supported: the book owner.

US4 design

Reconciliation uses a compact, color-coded 3-state C control (neutral white blank for Uncleared, amber R for Reconciling, and green ✓ for Cleared) instead of a wide text dropdown. In the main window, each JournalEntryLine for the selected account renders as its own row in the upper account register with its own 3-state C control: use ↑/↓ to navigate rows and press R, C, or U, or click C to cycle states. Because same-account lines are not combined into a single register row, no fourth Mixed summary state is needed and the lower entry-details pane's compact C column stays read-only. The journal editor also includes the color-coded 3-state C control in the Account → C → Debit → Credit Tab sequence: new lines default to Uncleared and preserve their chosen C state while editing fields before the initial save, whereas changing an already-saved Cleared or Reconciling line's account or amount auto-clears its C state to Uncleared with the reset warning.

Design references and spec overrides

The current WPF main window and journal editor are the design baseline. Earlier screenshots are used for spacing and the account rail only. The current spec overrides their older layouts: Payee with optional italic Description, status between Account and Debit, centered Debit/Credit headings with right-aligned values, live totals, mutually exclusive amount input, and reset warning/confirmation. The journal totals footing, row-tracking cues, and inline validation cues are now backported into spec.md and contracts/desktop-ui.md: the footing shows a bold Totals: prefix with Balanced or the short side named in red, numeric totals sit directly under their Debit/Credit columns with shared scrollbar-gutter alignment and without repeated labels or currency codes, the over-side total is red while unequal, each posting row shows a line number, alternate rows carry a continuous register stripe, and the hovered or focused row is highlighted in the register's selected-row color while inputs stay white. A line named in the reset warning shows an amber line number; a line with a validation error shows a 2px red input border and a red line-number pill that clear live when fixed. The WPF editor does not implement these additions yet.
